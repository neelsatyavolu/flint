**SwiftMail findings (read before touching `SwiftMailTransport`):**
- `fetchMessageInfos(using:)` expands the UID set into every identifier before chunking, so an open range (`N:*`) allocates four billion values and runs the test process out of memory. `SwiftMailTransport` uses the chunked stream only for lists and short ranges and a single FETCH for anything open.
- `BODY[HEADER.FIELDS (...)]` works on real servers but GreenMail omits the closing blank line and SwiftMail then returns no headers at all. The transport detects "no extra headers for any message in the batch", refetches with the full header once, and keeps using the full header on that connection (filtered to the requested names). References are not in `additionalFields`; they come from `MessageInfo.references`.
- `fetchStructure` lists leaf parts only; for a `message/rfc822` it lists the part and then the embedded parts. `BodyPartTree` rebuilds the tree so embedded parts stay inside their attachment. SwiftMail names an unnamed part after its Content-ID; `BodyPartTree` drops such names so bodies stay bodies and unnamed inline images get `inline-N.ext`.
- `fetchPart` returns the raw transfer-encoded bytes. The transport remembers each part's encoding from the structure it fetched (or fetches the structure on a miss) and decodes; charset conversion stays in `TextDecoding`.
- A tagged NO on MOVE comes back as `moveFailedAfterPossiblePartialCompletion`; the transport maps that to `.invalid` so the engine's create-the-folder-and-retry works. Partial evidence maps to `.conflict`.
- `IMAPServer.idle(on:)` opens its own connection and renews itself every 285 s, so the IDLE transport holds two connections to the server (its primary one is idle). Gmail allows about 15 per account, so keep one session per account.
- RFC 2231 file names (`filename*=`) are not decoded by SwiftMail (nor by several servers' BODYSTRUCTURE); `MimeBuilder` writes RFC 2047 encoded words in quotes instead, which SwiftMail, Gmail and Apple Mail read.
- `Capability` values are NIO types: use `.name`, not `String(describing:)`, to test for IDLE/QRESYNC/ENABLE.

**Lifecycle and background (4B):**
- `start()` wires the listeners once, then queues one-time maintenance (purge expired kv, replay `pending_ops`, mark interrupted sends failed, re-categorize when `categorizerVersion` changed, re-fetch categorization headers once per version) and starts the scheduler pump and every enabled account's session.
