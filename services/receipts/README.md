# Flint receipts service

Cloudflare Worker + D1. Serves the tracking pixel, classifies every hit, and exposes a small JSON API the Flint desktop app polls. Raw IP addresses are never stored: only truncated HMAC-SHA256 fingerprints.

## Deploy

```sh
cd services/receipts
pnpm install
npx wrangler d1 create flint-receipts           # copy the printed database_id into wrangler.toml
npx wrangler d1 migrations apply DB --remote
openssl rand -base64 32 | npx wrangler secret put FINGERPRINT_SALT
npx wrangler deploy
```

Then set the Worker URL (or a custom domain) as `settings.receipts.endpoint` in Flint. Keep `FINGERPRINT_SALT` stable: changing it makes old fingerprints unmatchable, so recent sender pings stop identifying the sender.

Local run: `npx wrangler d1 migrations apply DB --local && npx wrangler dev --local --var FINGERPRINT_SALT:dev`.
Tests: `pnpm test` (plain vitest with a node:sqlite D1 fake; `@cloudflare/vitest-pool-workers` 0.23 pins vitest 4.1 and the repo uses vitest 5).

## API

All errors are `{ "error": { "code", "message" } }`. CORS is closed (no `Access-Control-*` headers). Types and zod schemas are in `src/protocol.ts`.

| Endpoint | Notes |
| --- | --- |
| `POST /v1/install` | `{ installId, secret }`. 10 per hour per IP fingerprint. Stores `sha256(secret)`. |
| `POST /v1/messages` | `{ ref, recipients: [{ token }] }`, 1 to 100 tokens of `/^[A-Za-z0-9_-]{22}$/`. 201. Idempotent per `ref`. Records the caller as a sender fingerprint. |
| `DELETE /v1/messages/:ref` | Stops tracking and deletes the message's events. |
| `POST /v1/seen` | Records the caller fingerprint (24h TTL). |
| `GET /v1/events?after=&limit=` | `{ events, cursor }`. `limit` 1 to 500. Fingerprints are re-hashed per install. Events carry `possiblyForwarded`. |
| `GET /i/:token.gif` | Always returns the 43-byte GIF. Writes happen in `ctx.waitUntil`. |

Auth: `Authorization: Bearer <installId>.<secret>`, compared in constant time against the stored hash.

## Classification (`src/classify.ts`)

Order: self, prefetch, scanner, bot, duplicate, open. Only `open` counts. Ambiguous hits are marked non-open on purpose.

- self: fingerprint matches a sender fingerprint (registration or `/v1/seen`) from the last 24h.
- prefetch: IP inside Apple's egress list, Apple ASN 714 or 6185, or a bare `Mozilla/5.0` user agent from any network (no real mail client sends it; Apple's ranges drift, so the network is not required).
- scanner: HEAD; known scanner user agents; security-vendor organizations at any time (Proofpoint, Mimecast, Barracuda, IronPort, Trend Micro, Sophos, Fortinet, Forcepoint, Symantec/Broadcom, Zscaler and others); Google network without the `GoogleImageProxy` marker; Microsoft network without an Outlook client UA within 60s; hosting networks within 60s; the frozen Chrome 42 / Edge 12 user agent.
- bot: empty UA, HTTP libraries, headless browsers, link-preview bots, hosting networks after 60s, spoofed `GoogleImageProxy` UA.
- duplicate: same client and same fingerprint (any proxy IP for Gmail/Yahoo) within 10s of a counted open.
- open: everything else. `client` is Gmail, Yahoo Mail, Outlook, Thunderbird, Apple Mail, Spark, Superhuman and so on. Proxy clients (Gmail, Yahoo) store no country or city because that is the proxy's location.
- `possiblyForwarded`: a counted open whose fingerprint and client both differ from the first counted open and arrives more than 1h later.

### Apple range data

`src/apple-ranges.ts` is generated by `node scripts/gen-apple-ranges.mjs` from Apple's list. On 2026-10-25 the list had 285,105 rows that collapse into 641 IPv4 /24 blocks (Akamai 172.224-226/16, Cloudflare 104.28/16, Fastly 140.248/16 and 146.75/16) and 56 IPv6 /36 blocks. Re-run the script every few months; the match is coarse (the whole /24 or /36), which can only err toward "prefetch".

## Findings and sources

Verified against sources:

- Apple Mail Privacy Protection downloads remote content through Apple proxies at delivery, not at open, so the pixel fires for every message. Requests go through at least two relays and use a single unified user agent. SocketLabs: https://help.socketlabs.com/docs/identifying-apple-mpp-opens-in-notification-api-events . Mailgun tags these as bot `apple`: https://documentation.mailgun.com/docs/mailgun/user-manual/tracking-messages/open-click-bot-detect . Twilio SendGrid "Apple Open Indicator": https://www.twilio.com/docs/sendgrid/for-developers/tracking-events/understanding-apple-mail-privacy-protection-and-open-events
- Apple publishes the relay egress list at https://mask-api.icloud.com/egress-ip-ranges.csv and says to recognize relay traffic by that list: https://developer.apple.com/icloud/prepare-your-network-for-icloud-private-relay/ . The list is hosted on partner networks, so Apple's own ASN is not enough; this is why the IP list is embedded.
- Gmail: images load through Google's proxy with a user agent ending `(via ggpht.com GoogleImageProxy)`, cached after the first fetch, so later opens often never reach the sender (counts are a lower bound). https://www.gmass.co/blog/false-opens-in-gmail , https://support.google.com/mail/thread/181785447 , https://words.filippo.io/how-the-new-gmail-image-proxy-works-and-what-this-means-for-you/
- Gmail also makes separate prefetch and content-inspection requests with browser-like user agents and no `GoogleImageProxy` marker (controlled 2025 research summarized at https://www.suped.com/learn/email-deliverability/why-are-emails-showing-as-opened-with-google-image-proxy-ip-when-the-recipient-hasnt-opened-them ). Flint therefore counts Gmail only with the marker and treats other Google traffic as scanner.
- Yahoo: `YahooMailProxy; https://senders.yahooinc.com/mail-proxy-servers` user agent, Yahoo-owned IP ranges: https://senders.yahooinc.com/mail-proxy-servers
- Security gateways (Microsoft Defender Safe Links, Mimecast, Proofpoint, Barracuda) fetch links and images at delivery from rotating datacenter IPs with spoofed user agents: https://github.com/mautic/mautic/issues/16263 , https://learn.microsoft.com/en-us/defender-office-365/safe-links-about
- Trackers themselves say no pixel tracker is fully accurate and that proxy or scanner fetches cause false positives: https://mailsuite.com/blog/why-mailtrack-is-the-most-reliable-email-tracker

Not verified (treat as heuristics, tuned conservatively):

- The `Chrome/42.0.2311.135 ... Edge/12.246` frozen user agent is attributed to machine fetchers by two practitioner posts (https://dev.to/hyehugh/your-open-rate-is-inflated-by-three-machines-here-is-how-to-prove-it-d25 , https://pay.trytoolboxpro.com/blog/why-gmail-open-rates-are-inflated ) that disagree on whether it is Apple or Google. Either way it is not a reader, so it is never counted.
- Outlook.com / Microsoft 365 web image proxying: no authoritative source for its user agent. A Microsoft-network hit without a recognized Outlook UA is always a scanner, at any delay, so an M365 recipient reading in a browser may be missed rather than risk a false open.
- Outlook desktop UAs (`Microsoft Office/16.0 ... Microsoft Outlook`) are recalled from experience, not from a fetched source.
- Apple Mail without MPP is recognized as WebKit without a Safari token; other apps embedding WebKit may be labeled Apple Mail.
- A recipient on the same network as the sender within 24h of a ping is marked `self` (shared office NAT), which hides that real open.
